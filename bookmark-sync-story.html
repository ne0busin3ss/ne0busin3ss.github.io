Chrome leads, two browsers follow

How Claude and I built a bookmark mirror for my Linux desktop in one evening, and what my real bookmarks taught us that the tests couldn’t.

Dave Raymond, October 2026

The problem

I keep three browsers on my Linux desktop: Chrome, which holds my current bookmarks, plus Chromium and Firefox. I use more than one for testing, and as a fallback when a browser update occasionally breaks a site I depend on. Each browser has its own bookmark sync, but each only syncs with itself. Google syncs Chrome, Mozilla syncs Firefox, and they don’t talk to each other.

So the bookmarks drifted. A site saved in Chrome never reached Firefox. Until now, I exported my Chrome bookmarks to a file and imported it into the others by hand. With more than 400 bookmarks in about 80 folders, keeping up that way wasn’t realistic.

What I asked Claude for was simple: keep Chrome, Chromium and Firefox in sync, with Chrome as the primary copy. Microsoft Edge joined the list later that evening. I’ve since dropped Edge as more trouble than it was worth, but it taught us a lot along the way, as the timeline shows.

The approach

Before writing any code, Claude settled the ground rules. They turned out to matter more than any clever feature:

  • One-way mirror. Chrome is read, never written. Every other browser is made to match it exactly.
  • Never write to an open browser. A running browser overwrites its bookmark file when it closes, so the script waits until it’s closed.
  • Back up first, every time. The newest 10 copies of each browser’s bookmarks are kept.
  • Preview before acting. --dry-run shows every change without touching anything.
  • Nothing to install. Plain Python 3, nothing to download. It’s confirmed on Linux. The code also covers macOS and Windows, but those haven’t been tested yet.

Chrome and Chromium store bookmarks in the same JSON format, so Chromium is straightforward. (So do Edge and Brave, which the script also supports.) Firefox is the hard one: its bookmarks live in a SQLite database alongside your browsing history, with internal hash values and reference counts that Firefox expects to stay consistent. The script writes Firefox in a single database transaction, reuses existing history entries, and records deletions so Firefox Sync passes them on to other devices.

What happens on each sync

  1. Read Chrome’s bookmarksIncluding any saved to the Google account, merged without duplicates.
  2. Compare with each browserTitles, links, folders and order. If they already match, nothing is written.
  3. Wait if the browser is openIt’s noted once in the log and updated within a minute of closing.
  4. Back up, and save anything about to disappearBookmarks only that browser had are saved to a file Chrome can import.
  5. Write the new bookmarksAn atomic file swap for Chromium, one database transaction for Firefox.

The bug worth showing

The Edge problem is a good example of how small these fixes can be once the cause is clear. The comparison included the names of the top-level folders, and each browser chooses its own names:

# 1.3.0: compared everything, including the top folders' own names
return tuple(tree[r].signature() for r in roots)

# 1.3.1: compare only what's inside them
return tuple(tree[r].signature()[2] for r in roots)

Finding it was the hard part. The clue was a log line reporting “Edge: updated” while listing zero differences. If nothing was different, the comparison itself had to be wrong.

Running it day to day

The script runs as a Linux systemd user service. It starts when I log in, checks every 60 seconds, and logs what it does. I don’t think about it anymore: I bookmark in Chrome, and the other browsers have it the next time I open them.

Today it syncs Chromium and Firefox. When I retired Edge, nothing in the code had to change: the list of browsers to keep in step is one setting in the service.

Two practical lessons came out of setup. When I moved my code folder into ~/Development, the service quietly failed, because it still pointed at the old path. The log said so plainly, and one edit to the service file fixed it. And pushing my own changes to GitHub needed a sign-in, which the GitHub command-line tool (gh auth login) handled through the browser.

What I took away

  • Real data finds what tests can’t. The simulated profiles proved the logic was sound. My real 430 bookmarks found five problems nobody had imagined, and all five were fixed the same evening.
  • Make it safe before making it smart. The one scare, 24 Edge bookmarks removed, cost nothing, because the backup rule was in place from the very first version.
  • Short loops beat a long plan. Eight releases in one evening, each a quick cycle: run it, read the output, fix one thing, run it again.
  • Check the checker. Even the review fixes got tested, and that test found the last bug.

Try it yourself

The code, README and cheat sheet are on GitHub: ne0busin3ss/Python, Bookmark_Sync folder. Start with a preview. It doesn’t change anything.

git clone https://github.com/ne0busin3ss/Python.git
cd Python/Bookmark_Sync
python3 bookmark_sync.py --list
python3 bookmark_sync.py --dry-run

Tested on Linux only. It runs daily on my Linux desktop, and the background service uses Linux’s systemd. The macOS and Windows support is written but hasn’t been tried on a real machine yet.

It’s a mirror, so anything that exists only in the other browsers will be removed. It’s saved to an importable file first, but read the preview before your first real sync.
